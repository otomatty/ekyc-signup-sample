## 1. テストの段階

| 段階 | 対象 | 方法 | このサンプル |
|---|---|---|---|
| 単体 | 正規化、照合、署名、マスキング、入力チェック | pytest、Vitest | 自動 |
| 結合 | API の一連の流れ、バッチと kintone | pytest（TestClient、モック） | 自動 |
| E2E | 画面からの申込〜結果、バッチ | ブラウザでの手動確認（3章） | 手動 |
| 実機 | NFC での読み取り、スマホの OS・機種 | 実機 | 本番化の際に実施 |
| 受入 | 業務フロー、照合ルール、案内文 | ビジネス側 | 本番化の際に実施 |

## 2. 自動テスト

### 2.1 実行方法

```bash
cd backend && pytest          # バックエンド（45件）
cd frontend && npm test       # フロントエンド（7件）
cd frontend && npm run typecheck
```

### 2.2 一覧

| ファイル | 観点 |
|---|---|
| `backend/tests/test_normalize.py` | 漢数字、全角半角、ハイフン、丁目番地の書き方の違いをそろえられるか |
| `backend/tests/test_matcher.py` | 項目ごとの判定と総合判定（[照合ロジック設計書 5章](05_照合ロジック設計書.md#5-テストケース)） |
| `backend/tests/test_security.py` | トークンの改ざん・期限切れ、Webhook 署名の改ざん・リプレイ、マスキング |
| `backend/tests/test_api_flow.py` | 申込〜コールバック〜状態取得、重複コールバック、他人の申込の閲覧、入力チェック |
| `backend/tests/test_batch.py` | 登録・更新、2回目は何もしない、100件超の分割、途中失敗からの回復、リトライ、カード情報を送らない |
| `frontend/src/validators.test.ts` | 入力チェック、年齢計算、送信データの変換 |

## 3. E2E シナリオ（手動）

事前に backend と frontend を起動しておく（[README](../../README.md#起動方法)）。

| No | サンプル入力 | モック画面で選ぶカード | 期待する結果画面 | 内訳 |
|---|---|---|---|---|
| E-1 | 一致する | 山田 太郎 | 本人確認完了 | すべて一致 |
| E-2 | 異体字 | 髙橋 花子 | 担当者確認中 | 氏名が要確認 |
| E-3 | 建物名の有無 | 鈴木 一郎 | 担当者確認中 | 住所が要確認 |
| E-4 | 住所が違う | 佐藤 次郎 | 本人確認NG | 住所が不一致 |
| E-5 | 一致する | パスワードロック | 本人確認エラー（ロックの案内） | 「もう一度本人確認する」が出る |
| E-6 | 一致する | 電子証明書が失効 | 本人確認エラー（失効の案内） | 同上 |
| E-7 | 一致する | （「中断する」を押す） | 本人確認エラー（中断の案内） | 同上 |
| E-8 | （入力しない） | − | 申込画面でエラー表示 | 各項目にエラー |
| E-9 | − | − | `/result` を直接開くと申込画面へ | − |
| E-10 | E-1〜E-5 の後 | − | `python -m batch.sync_to_kintone` で5件登録、2回目は0件 | `http://localhost:8000/mock-kintone/debug/records` で確認 |
| E-11 | − | − | `MOCK_VENDOR_DUPLICATE_CALLBACK=true` で起動して E-1。ログに `duplicate callback ignored` | 結果は1件のみ |

## 4. 本番化に向けて追加するテストの観点

| 観点 | 内容 |
|---|---|
| 実機 | iPhone と Android の主要機種、OS バージョン。NFC の位置、ケースを付けたままの読み取り |
| ブラウザ | iOS Safari、Android Chrome、アプリ内ブラウザ（SNS からのリンク） |
| PC からの申込 | スマホへの引き継ぎ（QR コード）、途中で PC に戻った場合 |
| 中断・再開 | アプリを閉じる、電話がかかってくる、通信が切れる、戻るボタン |
| 外部障害 | ベンダーが落ちている、コールバックが届かない、遅れて届く |
| 文字 | 外字、旧字体、長い住所、外国籍の方の氏名 |
| 負荷 | キャンペーン時の申込集中。kintone の同時リクエスト数に収まるか |
| セキュリティ | 脆弱性診断、トークンの改ざん、他人の申込の閲覧 |

## 5. 合否の基準

- 自動テストがすべて成功する
- E2E シナリオ E-1〜E-11 が期待どおり
- ログに個人情報（住所、電話番号、メール、生年月日）が出ていない
