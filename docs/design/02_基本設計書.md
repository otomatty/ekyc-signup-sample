### 1.1 本番構成との対応（例）

| サンプル | 本番の構成例 | 備考 |
|---|---|---|
| 申込画面（Vue） | フォーム SaaS（クライゼルなど）の申込フォーム | ノーコード。項目追加や遷移の変更が改修対象 |
| 本人確認画面・結果画面（Vue） | eKYC フォーム（Vue.js） | 自前開発 |
| 本体 API（FastAPI） | eKYC フォームのバックエンド（FastAPI） | 自前開発 |
| SQLite | フォーム SaaS 側の DB、または自前の DB | 構成によって異なる |
| モックベンダー | e-NINSHO などの PF 事業者 | 実際はアプリ／SDK で IC チップを読む |
| モック kintone | kintone | 審査担当が使う |
| 同期バッチ | GCP 上の Python バッチ | Cloud Run Jobs ＋ Cloud Scheduler など |

## 4. 処理フロー

```mermaid
sequenceDiagram
  autonumber
  actor U as 申込者
  participant FE as frontend
  participant API as backend /api
  participant V as モックベンダー
  participant BT as 同期バッチ
  participant KT as モック kintone

  U->>FE: 申込内容を入力
  FE->>API: POST /api/applications
  API-->>FE: 申込ID ＋ 受け渡しトークン
  U->>FE: 本人確認を始める
  FE->>API: POST /api/ekyc/sessions（トークン）
  API->>V: POST /v1/sessions（APIキー）
  V-->>API: session_id ＋ verify_url
  API-->>FE: verify_url
  FE->>V: 画面遷移（ページごと移動）
  U->>V: カード選択・パスワード入力
  V-->>FE: 303 リダイレクト（/result）
  V->>API: POST /api/ekyc/callback（署名付き）
  API->>API: 署名検証 → 照合 → 保存
  loop 結果が出るまで
    FE->>API: GET /api/applications/{id}
  end
  BT->>BT: DB から未連携の申込を抽出
  BT->>KT: 申込IDで検索 → 登録／更新
```

コールバック（12）は画面のリダイレクト（11）と非同期に届くため、結果画面は状態が確定するまでポーリングする。

## 6. 申込の状態遷移

```mermaid
stateDiagram-v2
  [*] --> APPLIED: 申込
  APPLIED --> EKYC_IN_PROGRESS: 本人確認開始
  EKYC_IN_PROGRESS --> VERIFIED: 照合 すべて一致
  EKYC_IN_PROGRESS --> NEEDS_REVIEW: 照合 一部一致あり
  EKYC_IN_PROGRESS --> REJECTED: 照合 不一致あり
  EKYC_IN_PROGRESS --> EKYC_FAILED: ロック・失効・中断
  EKYC_IN_PROGRESS --> EKYC_IN_PROGRESS: 再開始
  EKYC_FAILED --> EKYC_IN_PROGRESS: 再試行
  VERIFIED --> [*]
  NEEDS_REVIEW --> [*]
  REJECTED --> [*]
```

| 状態 | 画面表示 | 再試行 | kintone 連携 |
|---|---|---|---|
| APPLIED | 申込受付 | 可 | しない |
| EKYC_IN_PROGRESS | 本人確認中 | 可 | しない |
| VERIFIED | 本人確認完了 | 不可 | する |
| NEEDS_REVIEW | 担当者確認中 | 不可 | する |
| REJECTED | 本人確認NG | 不可 | する |
| EKYC_FAILED | 本人確認エラー（理由別の案内） | 可 | する |

## 7. エラー処理の方針

| 種類 | 例 | 対応 |
|---|---|---|
| 入力エラー | 必須漏れ、18歳未満 | 画面で即時に表示。サーバーでも 422 で弾く |
| 認証エラー | トークン期限切れ | 401。画面で「最初からやり直す」を表示 |
| 状態エラー | 本人確認済みの申込で再開始 | 409。結果画面へ移動 |
| 外部の一時障害 | ベンダーや kintone の 5xx、通信エラー | 指数バックオフで最大3回リトライ。だめなら 502 またはバッチ失敗 |
| 外部の恒久エラー | 4xx | リトライしない。ログに残して失敗扱い |
| 重複 | コールバックの再送 | 200 で受け、処理はしない |

## 8. ログの方針

- 出してよいもの: 申込ID、セッションID、状態、件数、エラーの種類
- 出さないもの: 氏名、住所、電話番号、メール、生年月日、カードの読み取り値
- 識別が必要な場合だけ、マスクした値を出す（例: `山田 ＊＊`）

詳細は [セキュリティ設計書](06_セキュリティ設計書.md#4-ログ出力のルール)。
