# セキュリティ設計書

| 版 | 日付 | 内容 |
|---|---|---|
| 0.1 | 2026-10-28 | 初版 |

本人確認は機微な個人情報を扱います。このサンプルで実装している対策と、本番に向けて追加が必要な対策を整理します。

---

## 1. 脅威と対策

| No | 脅威 | 対策 | 実装 |
|---|---|---|---|
| S-1 | 申込IDを書き換え、他人の申込で本人確認を進める | 申込IDに HMAC 署名と有効期限を付けたトークンで受け渡す | `security.issue_handoff_token` |
| S-2 | 他人の申込の状態を見る（IDOR） | トークンの申込IDとパスの申込IDを照合。違えば 404 | `routers/applications.py` |
| S-3 | 偽のコールバックで本人確認を通す | HMAC-SHA256 署名を検証。比較は定数時間（`hmac.compare_digest`） | `security.verify_webhook` |
| S-4 | 盗んだコールバックを後で再送する（リプレイ） | 署名にタイムスタンプを含め、5分以上ずれたものを拒否 | 同上 |
| S-5 | 同じコールバックの重複で二重処理 | `event_id` に UNIQUE 制約 | `ekyc_results.event_id` |
| S-6 | 別の申込のセッションを使った結果の差し込み | セッションと申込IDの組み合わせを確認 | `routers/ekyc.py` |
| S-7 | ベンダー API の不正利用 | APIキーで認証 | モックベンダー |
| S-8 | 画面へのスクリプト埋め込み（XSS） | Vue のテンプレートは自動でエスケープ。モックの HTML は `html.escape` | − |
| S-9 | 別サイトからの API 呼び出し | CORS で許可するオリジンを限定 | `main.py` |
| S-10 | 秘密情報の漏えい | 鍵やトークンをコードに書かず、環境変数から読む。`.env` は Git に含めない | `config.py`、`.gitignore` |
| S-11 | ログからの個人情報漏えい | ログに個人情報を出さない。必要な場合はマスク | `masking.py` |
| S-12 | 個人番号の取得 | 個人番号を扱わない。JPKI の署名用電子証明書には個人番号は含まれない | − |
| S-13 | 連携先からの漏えい | kintone にはカードの読み取り値を送らない | `batch/sync_to_kintone.py` |

## 2. 個人情報の流れ

| データ | 取得元 | 保存先 | 申込者の画面 | kintone | ログ |
|---|---|---|---|---|---|
| 申込内容（氏名、住所など） | 申込フォーム | DB | 氏名のみマスクして表示 | 送る（審査に必要） | 出さない |
| カードの基本4情報 | ベンダー | DB（本人確認記録） | 出さない | **送らない** | 出さない |
| 照合の判定 | システム | DB | 項目名と判定のみ | 要約を送る | 状態のみ |
| 受け渡しトークン | システム | ブラウザの sessionStorage | − | − | 出さない |

## 3. 秘密情報

| 名前 | 用途 | 本番での管理（想定） |
|---|---|---|
| APP_SECRET | 受け渡しトークンの署名 | Secret Manager。定期的に更新 |
| VENDOR_API_KEY | ベンダー API の認証 | Secret Manager |
| VENDOR_WEBHOOK_SECRET | コールバック署名の検証 | Secret Manager |
| KINTONE_API_TOKEN | kintone API の認証 | Secret Manager。必要なアプリ・権限だけに絞って発行 |

---

## 4. ログ出力のルール

| 区分 | 例 | 扱い |
|---|---|---|
| 出してよい | 申込ID、セッションID、状態、件数、HTTP ステータス、エラーの種類 | そのまま出す |
| マスクして出す | 氏名（`山田 ＊＊`）、電話番号（`*******5678`） | 調査に必要な場合だけ |
| 出さない | 住所、生年月日、メール、カードの読み取り値、トークン、署名 | 出さない |

実装例（`routers/applications.py`）:

```python
logger.info("application created id=%s name=%s", application_id, mask_name(body.name))
```

---

## 5. ブラウザ側

- 受け渡しトークンは **sessionStorage** に保存する。タブを閉じると消え、ほかのタブからは見えない
- localStorage や Cookie に長期間残さない
- トークンの有効期限は30分。切れたら最初からやり直す

---

## 6. 本番化に向けて追加が必要な対策

このサンプルでは実装していないものです。

| 対策 | 内容 |
|---|---|
| 通信の暗号化 | すべて HTTPS。HSTS の設定 |
| DB の暗号化 | 保存時の暗号化、本人確認記録の列単位の暗号化 |
| アクセス制御・監査 | 本人確認記録を見られる人の制限と、閲覧の記録 |
| レート制限 | 申込 API、本人確認開始 API への大量アクセス対策（WAF など） |
| 送信元の制限 | コールバックの送信元 IP の制限（ベンダーが公開している場合） |
| 鍵の更新 | シークレットを定期的に更新し、更新中は新旧両方を受け付ける |
| データ削除 | 保存期間を過ぎた本人確認記録の削除 |
| 脆弱性診断 | リリース前の診断、依存ライブラリの脆弱性チェック |
| AI ツールの利用 | 本番データや個人情報を AI ツールに入力しない。社内ルールに従う |
