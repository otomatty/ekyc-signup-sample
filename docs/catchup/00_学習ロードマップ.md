# 学習ロードマップ

**想定する読み手:** React での開発経験があり、直近は設計・マネジメントが中心で、API の実装からしばらく離れている人。

**ゴール:** このような構成のプロジェクトに入った初週に、eKYC フォーム（Vue.js＋FastAPI）、GCP のバッチ、kintone 連携の話についていける。この領域の論点を自分の言葉で説明できる。

目安は合計で 5 日（1日 2〜3 時間）です。

---

## Day 1　まず動かして、全体をつかむ

- [ ] [README](../../README.md) の手順で backend と frontend を起動する
- [ ] サンプル入力の4パターンと、モック画面のパスワードロックを試し、結果の違いを見る
- [ ] `http://localhost:8000/docs` で API 一覧を眺める
- [ ] バッチを実行し、`http://localhost:8000/mock-kintone/debug/records` で kintone 側の結果を見る
- [ ] [基本設計書](../design/02_基本設計書.md) のシーケンス図と、いま触った画面を対応させる
- [ ] [eKYCとJPKIの基礎](03_eKYCとJPKIの基礎.md) を読む

**確認:** 「申込 → 本人確認 → コールバック → 照合 → kintone」の流れを、図を見ずに説明できる。

## Day 2　Vue 3 に慣れる

- [ ] [React開発者のためのVue3入門](01_React開発者のためのVue3入門.md) を読む
- [ ] 次の順でコードを読む（下の表）
- [ ] 演習課題 1（プランの追加）をやる

| 順 | ファイル | 見るところ |
|---|---|---|
| 1 | `frontend/src/components/FormField.vue` | `defineModel`、`defineProps`、`v-if`、`v-for` |
| 2 | `frontend/src/pages/ApplyPage.vue` | `reactive`、`computed`、`v-model`、`@submit.prevent` |
| 3 | `frontend/src/stores/application.ts` | Pinia の Setup Store、sessionStorage を使う理由 |
| 4 | `frontend/src/composables/usePolling.ts` | composable（カスタムフック相当）、`onScopeDispose` |
| 5 | `frontend/src/pages/ResultPage.vue` | composable の使い方、`onMounted` |
| 6 | `frontend/src/router.ts` | ルート定義、ナビゲーションガード |

**確認:** `ref` と `reactive` の違い、`.value` が要る場所と要らない場所を説明できる。

## Day 3　FastAPI の勘を取り戻す

- [ ] [FastAPI復習ガイド](02_FastAPI復習ガイド.md) を読む
- [ ] 次の順でコードを読む
- [ ] `pytest -v` を実行し、テスト名から仕様を読み取る
- [ ] 演習課題 2〜3 をやる

| 順 | ファイル | 見るところ |
|---|---|---|
| 1 | `backend/app/models.py` | Pydantic のモデル、`field_validator`、`model_validator` |
| 2 | `backend/app/routers/applications.py` | エンドポイント、`Depends`、`HTTPException` |
| 3 | `backend/app/deps.py` | 依存性の組み立て、ヘッダーからの認証 |
| 4 | `backend/app/routers/ekyc.py` | 外部 API 呼び出し、Webhook の受信 |
| 5 | `backend/app/services/ekyc_vendor.py` | タイムアウト、リトライ |
| 6 | `backend/tests/conftest.py` | `dependency_overrides`、外部呼び出しの差し替え |

**確認:** Webhook の受信で「署名を生の本文で検証する」「重複には 200 を返す」理由を説明できる。
